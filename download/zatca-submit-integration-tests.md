## What This Tests

This integration test exercises the **production ZATCA submission pipeline** (from `src/lib/e-invoicing/zatca.ts`):

1. **`validateZatcaInvoice`** — validates invoice + company against ZATCA Phase 2 rules (VAT, dates, line items, etc.)
2. **`determineZatcaInvoiceType`** — classifies as Standard (B2B) or Simplified (B2C)
3. **`autoPopulateZatcaFields`** — generates UUID, formats dual dates, fills PIH
4. **`generateZatcaUblXml`** — generates UBL 2.1 XML with ZATCA extensions (QR code TLV, signature envelope)
5. **`signZatcaInvoice`** — signs XML with ECDSA-SHA256 using a P-256 key pair
6. **EInvoice persistence** — verifies the row is created with correct `submissionStatus`, `uuid`, `clearedAt`
7. **Audit log** — verifies `action='zatca_invoice_submitted'` is written
8. **E2E** — runs the full pipeline end-to-end on both valid and invalid invoices

**What's mocked:** the DB (in-memory store) and the actual HTTP call to ZATCA's API (requires real CSID/CCD certificates).
**What's real:** all the ZATCA validation, XML generation, and signing logic — the same code that runs in production.
