## Root-cause finding (read this first)

### R-1. Prisma client / schema.prisma drift

`prisma/schema.prisma` declares **98 models** (latest commit `1725725` added many of them under "P0-1: Full Runtime Model Sync"). However, the generated Prisma client in `node_modules/.prisma/client/index.d.ts` only knows about **52 models**. The following 8 models are referenced by route handlers but **do not exist in the generated client**:

| Schema model          | Route handlers that reference it (`db.<model>`)                                                                                                | Effect at runtime                                                                          |
| --------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------ |
| `WebhookEndpoint`     | `webhooks/endpoints/route.ts`, `webhooks/endpoints/[id]/route.ts`, `webhooks/events/route.ts`, `webhooks/deliveries/route.ts`                 | `db.webhookEndpoint` is `undefined`; every call throws `TypeError: Cannot read property 'findMany' of undefined` |
| `WebhookDelivery`     | `webhooks/deliveries/route.ts`, `webhooks/endpoints/[id]/route.ts`                                                                             | same                                                                                       |
| `InvoiceTemplate`     | `invoice-templates/route.ts`, `invoice-templates/[id]/route.ts`                                                                                | same                                                                                       |
| `InvoiceTemplateSettings` | `invoice-templates/route.ts`                                                                                                                | same                                                                                       |
| `AIMemoryNote`        | `ai/memory/route.ts`, `ai/memory/[id]/route.ts`                                                                                                | same (note: schema name `AIMemoryNote`, but client has the older `AIMemoryEntry` model — they are different tables) |
| `ChatHistory`         | `ai/chat/route.ts`, `ai/chat/stream/route.ts`                                                                                                   | same                                                                                       |
| `IdempotencyKey`      | `invoices/[id]/payment/route.ts` (H5 idempotency check + persistence)                                                                          | same — payment idempotency layer is silently disabled (the try/catch swallows the error)   |

The client also stores data with field names that don't exist in the actual Prisma model — e.g. `db.aIMemoryNote.create({ data: { entityType, entityId, note, createdBy } })` references 4 columns that are not on the `AIMemoryNote` Prisma model in `schema.prisma` (which only has `category, content, confidence`). The migration `20260720202945_init_ai_fabric/migration.sql` line 748 declares those columns at the SQL level, but the Prisma schema declaration is still wrong — so even after regenerating the client, those fields would be Prisma-unknown.

**Fix (1 command):** `bun run db:generate` to regenerate the client from the current `schema.prisma`. Then run `bunx tsc --noEmit` and fix every compile error that surfaces (there will be many). Consider removing the `db: any` annotation in `src/lib/db.ts` so the type system catches drift going forward.

### R-2. `db: any` defeats all type safety

`src/lib/db.ts:69` declares `export const db: any = globalForPrisma.prisma ?? extendedPrisma;`. The comment says "type as any to avoid TS extension type issues". This single annotation hides:

- Missing Prisma models (R-1 above).
- Field-name mismatches between Prisma schema and route-handler writes (e.g. `db.invoice.create({ data: { clientCompany: ... } })` when the schema calls the column something else).
- Incorrect ID types (passing `Number(cuid)` to `findUnique({ where: { id } })` for a `String @id` column).

**Fix:** Remove `: any`. Run `bunx tsc --noEmit`. Fix every error. If the `$extends` type is unwieldy, use `typeof extendedPrisma` instead.
