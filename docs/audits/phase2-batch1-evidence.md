## SEC-04: Valkey Fail-Closed for Writes — ✅ FIXED

### Problem
MFA rate limiting, JWT blacklist, and session registry all fail-OPEN on Valkey
outage. An attacker could brute-force TOTP codes or use revoked tokens during
a Valkey outage.

### Fix
Modified `src/lib/auth.ts` and `src/lib/mfa.ts`:

1. **`isTokenBlacklisted()`**: Returns `true` (reject token) when Valkey is down
   - Gated by `VALKEY_FAIL_MODE` env var (default: "closed", legacy: "open")
2. **`blacklistToken()`**: Throws error when Valkey is down (caller knows revocation failed)
3. **`validateMFA()`**: Returns `false` (reject MFA) when Valkey is down
   - Prevents brute-force during outage

### Tests Updated
- `blacklistToken with TTL <= 0` → now expects throw (was: does nothing)
- `blacklistToken with negative TTL` → now expects throw (was: does nothing)

## SEC-06: Login Generic Message + Rate Limit After MFA — ✅ FIXED

### Problem
Login returned `mfaRequired: true` after correct password (leaks credential
validity). Rate limits were cleared before MFA check (brute-force MFA possible).

### Fix
Modified `src/app/api/auth/login/route.ts`:
1. All 4 failure paths (user not found, wrong password, MFA missing, MFA wrong)
   return the SAME generic message: `"بيانات الدخول غير صحيحة أو التحقق الثنائي مطلوب"`
2. Rate limits (`auth:login` + `auth:login-email`) are cleared ONLY after
   full MFA validation succeeds (not after password check)
3. Server-side `logAudit` entries preserved for forensics (don't leak to client)
